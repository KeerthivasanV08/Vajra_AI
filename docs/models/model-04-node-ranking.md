# Model 04 — Node-Level Top-K Re-Ranker Model

> **Model ID**: `model4_node_ranker`  
> **Artifact Path**: `backend/models/node_ranker_model.joblib`  
> **Preprocessor Path**: `backend/models/node_ranker_preprocessor.joblib`  
> **Evaluation Report**: `backend/evaluation/model4_node_ranking_metrics.json`  
> **Visualizations**: [`docs/images/model4_node_ranking/`](../images/model4_node_ranking/)

---

## 1. Executive Summary & Purpose

Model 4 re-ranks the Top-20 candidate withdrawal nodes generated by the non-ML spatial candidate generator. It evaluates candidate distance, terminal vulnerability, local 5km fraud density, and digital risk signals to select the Top-3 operational cash-out terminals.

---

## 2. Model Specifications & Hyperparameters

- **Algorithm**: `XGBClassifier` (XGBoost Candidate Ranking)
- **Target Variable**: `is_actual_cashout_node` (Binary 0/1 indicating true cash-out terminal)
- **Training Dataset**: `node_ranking_candidates.csv`
- **Train / Validation / Test Split**:
  - Train: 420,000 candidate-pair rows (70%)
  - Validation: 90,000 candidate-pair rows (15%)
  - Test: 90,000 candidate-pair rows (15%)
- **Random Seed**: `42`
- **Training Timestamp**: `2026-09-27T01:23:24`

---

## 3. Input Features & Schema

| Feature Name | Type | Description | Preprocessing |
| :--- | :--- | :--- | :--- |
| `candidate_distance_km` | `float` | Distance from predicted trajectory point to node (km) | Standard Scaling |
| `node_vulnerability_score` | `float` | Terminal risk score from Model 2 (0.0–1.0) | Standard Scaling |
| `fraud_density_5km` | `float` | Historical fraud incidents within 5km radius | Log Standard Scaling |
| `historical_cashout_rate` | `float` | Terminal historical cash-out ratio | Standard Scaling |
| `trajectory_confidence` | `float` | Model 1 trajectory prediction confidence (0.0–1.0) | Standard Scaling |
| `digital_risk_score` | `float` | Digital AML risk score (0.0–1.0) | Standard Scaling |
| `mule_probability` | `float` | Mule account probability score (0.0–1.0) | Standard Scaling |
| `time_of_day` | `int` | Hour of day (0–23) | Cyclical Encoding |
| `day_of_week` | `int` | Day of week (0–6) | Cyclical Encoding |

## 5. Audit & Candidate Distance Dependencies

- **Non-ML Candidate Prerequisite**: Candidate generation MUST occur prior to Model 4 invocation. Model 4 does NOT generate candidate nodes; it re-ranks the Top-20 shortlist.
- **Distance Feature Dependency**: `candidate_distance_km` is a strong predictive feature.
- **Audit Status**: `PASS_WITH_WARNINGS` (High ranking metrics driven by synthetic candidate proximity distribution).
